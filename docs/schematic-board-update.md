# Selected schematic-to-PCB updates

These operations update selected board footprints from the schematic.
They are not a complete replacement for KiCad Update PCB from Schematic.

```python
from eedesigncore import (
    BoardUpdateSelection, GuardedDocument, SourceSnapshot,
    inspect_schematic_electrical, load_guarded_document,
    plan_schematic_board_update, apply_schematic_board_update,
    save_guarded_documents,
)

# Capture every schematic and project dependency before inspection.
dependencies = [SourceSnapshot.capture(path) for path in input_paths]
inspection = inspect_schematic_electrical(project_path, document_id="update")
assert {str(s.path): s.sha256 for s in dependencies} == inspection.source_hashes
entry = load_guarded_document(board_path)
selection = BoardUpdateSelection(footprint_uuid=chosen_uuid, symbol_id=chosen_symbol_id)
plan = plan_schematic_board_update(entry.document, inspection, selections=[selection])
if plan.blockers:
    raise ValueError(plan.blockers)
updated = apply_schematic_board_update(entry.document, inspection, plan)
save_guarded_documents([GuardedDocument(entry.source, updated)], dependencies=dependencies)
```

The caller supplies exact board footprint UUIDs and occurrence-qualified symbol IDs.
There is no reference fallback or automatic selection. Unselected footprints remain unchanged.
The plan reports associations, pad assignments, positions, angles, sides, locks, notes, and blockers.
Apply rechecks the complete plan against both inputs and returns a detached Board.
Apply does not write files. A changed input or altered plan requires a new plan.

The default footprint policy requires equal selected library identifiers.
`footprint_policy="preserve_existing"` permits a mismatch only by explicit choice.
It keeps the current footprint geometry. It does not prove that the board and library match.
Neither policy loads or refreshes library geometry. Equal identifiers do not prove equal geometry.

`update_reference=True` changes the existing Reference field value. It preserves its text formatting.
`update_pad_nets=False` selects association-only operation for mechanical footprints that have no electrical pads.
Value, population flags, footprint library identifiers, and other metadata remain unchanged.
Footprint geometry, placement, side, lock state, UUIDs, groups, tracks, and zones remain unchanged.

Duplicate physical pads with one number receive the same resolved schematic net.
Explicit no-connect pads remain unassigned. An existing assigned net blocks that no-connect update.
An isolated autogenerated unconnected net without no-connect evidence blocks the update.
The operation does not invent no-connect names or claim native forward-annotation parity.
Missing or ambiguous pads, incomplete electrical coverage, and multi-unit references block the operation.
Changed pad assignments on nets referenced by routed copper, zones, or copper graphics also block it.
Unrelated copper remains unchanged. This does not prove physical copper connectivity or design-rule compliance.

Footprint replacement, addition, deletion, routed-net reassignment, and full metadata propagation are unsupported.
These require separate operations. This helper never substitutes a footprint insertion for a refresh.

Guarded saves accept Board, Schematic, and ProjectFile. They compare exact captured source bytes.
Unchanged documents retain their original bytes and modification time.
Capture and pass all input dependencies when saving a derived update.
The inspection hash alone does not capture current bytes for a later guarded save.
Multiple file replacements are not atomic. Partial failures carry per-file outcomes.
Guards cannot detect unsaved GUI edits or eliminate races with writers that ignore their locks.
